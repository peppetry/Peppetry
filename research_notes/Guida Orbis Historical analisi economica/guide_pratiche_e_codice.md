Research date: 2026-10-07. Environment constraints that shaped this note: GitHub code search and `raw.githubusercontent.com` were reachable, so every code finding below was read in full from the raw file. Almost all non-GitHub hosts (nber.org, aeaweb.org, openicpsr.org, oecd.org, iwh-halle.de, ecb.europa.eu, imf.org, wrds-www.wharton.upenn.edu, library guides at Yale/HBS/Princeton/WU/CBS, zenodo.org, LSE eprints) were blocked by the network egress proxy, and the web-search budget ran out before a second pass. Findings from those sources therefore rest on search-result snippets and are flagged "(snippet only, not verified in full text)". Nothing below is invented; where a rule could not be read it is listed under Gaps.

Glossary used throughout: Orbis consolidation codes C1 = consolidated statement with no unconsolidated companion; C2 = consolidated with an unconsolidated companion; U1 = unconsolidated with no consolidated companion; U2 = unconsolidated with a consolidated companion; LF = "limited financials". These definitions are quoted from the LexisNexis Orbis Report help page: "C1: Statement of a mother company integrating the statements of its controlled subsidiaries or branches with no unconsolidated companion; C2: ... with an unconsolidated companion; U1: Statement not integrating the statements of the possible controlled subsidiaries or branches of the concerned company with no unconsolidated companion; U2: ... with an unconsolidated companion" — [LexisNexis Orbis Report help](https://riskmanagement.lexisnexis.com/bps/web20_help/RSKM/bsp_results_orbisreport_r.html) (snippet only).

## Key question 1 — Which GitHub/GitLab repositories process Orbis flat files or Orbis Historical, and what exactly do they do?

### Takeaway
There is no mature, general-purpose open-source "Orbis cleaning" package; what exists is a scattered set of project repositories. Four of them are directly relevant to Moody's bulk flat files (panel-e2tree's awk streaming extractor, Tax Justice Network's Key_financials streamer, EquityOwnershipStructure's Orbis Historical financials + Links_YYYY processing, and firmpanel's DuckDB/Spark pipeline modelled on Moody's DataHub tables), while the rest work on WRDS Orbis tables or web exports but contain reusable deduplication rules.

### Inferences
- Deduplication conventions diverge sharply across repos: macro/productivity work (gjardad; panel-e2tree; fabulaye) prefers **unconsolidated** statements; accounting/finance work (Gassen; JAR 60; fin5; firmpanel default ordering) prefers **consolidated**; Big-Bang follows the Kalemli-Özcan hybrid. Any guide should state the choice explicitly rather than treat one as standard.
- The near-universal practical key for a statement in the bulk files is `(BvD ID, consolidation code, filing type, closing date)`; "one per firm-year" is then a second, rule-based collapse (prefer 12 months, prefer annual report, prefer latest closing date, then completeness).
- The two code bases that actually touch Orbis Historical (EquityOwnershipStructure, MM2026) show the delivery is multi-part RAR of tab-delimited TXT with a BOM on the first header, ISO-8859-1 encoding in older vintages, and separate `Financials/`, `Descriptive/`, `Ownership/` folders.

### Gaps
- No repo was found that implements BvD-ID-change handling (no file or column such as an ID-change mapping appears in any fetched script).
- MM2026's actual `ORBIS_1_MERGE.do`, firmpanel's `pipelines/financials.py`, and TJN's `1b_2_assemble.py` (the Links join) could not be fetched (directory listings and some raw paths blocked/404).
- GitLab was not searchable from this environment; Zenodo/openICPSR/Dataverse listings could not be opened.

## Key question 2 — Which university or data-center handbooks explain Orbis for researchers (WRDS, Bundesbank, CompNet, OECD, library guides)?

### Takeaway
Library guides exist at Yale, HBS, Princeton, WU Vienna, CBS, LUISS and others, and WRDS, CompNet (IWH) and the OECD publish relevant manuals, but all were egress-blocked here; only their search snippets could be captured. The most substantive methodological handbook for Orbis bulk panels remains the Kalemli-Özcan et al. paper (see Q3), which the library guides themselves quote.

### Cited Findings
- HBS Baker Library page "Orbis Historical" (snippet only): "Orbis Historical Data is a point-in-time snapshot of the Orbis entity database, delivered outside of the Orbis web interface via FTP in structured sets of tab delimited TXT or SQL table files, updated twice yearly in April and October. Orbis Historical contains all company financials collected back to 1995 as well as ownership changes back to 2007." and "Descriptive data in Orbis Historical is not cumulative or historical—it is a snapshot of each period and therefore header data that cannot be used for historical industry or geography." — [HBS Orbis Historical](https://www.library.hbs.edu/databases-cases-and-more/datasets/orbis-historical)

## Key question 3 — Replication packages for published papers with Orbis cleaning code: which files and rules?

## Key question 4 — Tutorials on efficiently handling the very large Orbis Historical files (tens of GB)

### Takeaway
No dedicated tutorial on Orbis + DuckDB/Polars was found; the practical patterns come from the repos: stream once with awk and pre-filter by BvD ID prefix (panel-e2tree), stream Python line-by-line with header-indexed columns (TJN), chunked pandas with `usecols` (jakob-ra, fin5), dask with explicit dtypes and ISO-8859-1 (EquityOwnershipStructure), convert to parquet and query with DuckDB using the original long column names (TRR266), or DuckDB/Spark with window-function dedup (firmpanel).

### Cited Findings
- awk single-pass extraction with country pre-filter by BvD ID prefix and `LC_ALL=C` for speed; scripts write a reduced TSV per table and warn to re-verify column positions per vintage (`head -1 FILE | tr '\t' '\n' | nl`). — [00_extract_orbis.sh](https://github.com/agostinognasso/panel-e2tree/blob/main/code/00_extract_orbis.sh)
- Pure-Python streaming of a 49 GB `Key_financials-EUR.txt` with progress every 20 million rows and header-name lookups (`idx = {c.strip().lower(): i for i, c in enumerate(hdr)}`), opening with `encoding="utf-8-sig", errors="replace"` to swallow the BOM. — [1b_1_financials.py](https://github.com/Tax-Justice-Network/unitary-taxation/blob/main/src/1b_orbis_universe/1b_1_financials.py)
- Chunked pandas: `pd.read_csv('Industry-Global_financials_and_ratios.txt', sep='\t', usecols=cols, chunksize=10000000)` then filter each chunk against a BvD-ID set. — [unzip_orbis.ipynb](https://github.com/jakob-ra/financial_news/blob/master/unzip_orbis.ipynb)
- dask with explicit `dtype={'Accounting practice': 'str', 'Audit status': 'str', ... 'Added value': 'str'}` to avoid mixed-type inference failures, `lineterminator='\n'`, `encoding="ISO-8859-1"`, then `.compute()` after the country filter; Links files handled year by year (`Links_2007.txt` … `Links_2020.txt`). — [processHist.py](https://github.com/YiLulululu/EquityOwnershipStructure/blob/main/processHist.py)
- DuckDB over parquet copies of the bulk files, selecting columns by their original quoted header names (`"BvD ID number"`, `"Number of months"`, `"Consolidation code"`) and filtering `WHERE "BvD ID number" LIKE 'DE%'` per country in a loop. — [2_number_bs_is.R](https://github.com/trr266/disclosure_regulation_around_the_world/blob/main/code/2_number_bs_is.R)
- firmpanel: same pipeline code targets DuckDB (laptop) or PySpark (Moody's DataHub); deterministic dedup via `row_number() OVER (PARTITION BY … ORDER BY …) = 1`, recursive CTE with cycle guard for ownership; README reports the 2023 DataHub run sizes (firm universe 38.6 M rows; unconsolidated balance sheet peak intermediate 552.7 M rows; final egress "24.7 GB across 11 files over SFTP"). — [firmpanel README](https://github.com/usama-jamal/firmpanel); [ownership.py](https://github.com/usama-jamal/firmpanel/blob/main/src/firmpanel/ownership.py)
- Stata route (MM2026): raw multi-part RAR extracted by the master do-file with an external `APP_UNRAR` path, converted to `.dta` with an English dictionary; documented runtime "1 day" for the Orbis Historical cleaning. — [MM2026 README](https://github.com/economoser/MM2026)
- WRDS route for large pulls: query by country and by size table, and for the huge small-company tables use `bvdid LIKE 'XX%'` instead of year filters; retry up to 3 times. — [wrds_parse main.ipynb](https://github.com/sunchojack/wrds_parse/blob/master/main.ipynb)
- Generic DuckDB/Polars teaching material exists (e.g. Grant McDermott's "duckdb-polars" workshop), but none mentions Orbis. — [duckdb-polars workshop](https://github.com/grantmcdermott/duckdb-polars)

### Inferences
- The consistent trick across all stacks is to exploit the BvD ID's two-letter country prefix to shard the files before any join; this avoids reading `Contact_info` at all.
- Encoding/BOM handling (`ï»¿BvD ID number` vs `utf-8-sig`) and string-typed "Number of months" are the two most common breakage points reported in code comments.

### Gaps
- No benchmark or blog post comparing Stata vs DuckDB vs Polars specifically on Orbis Historical files was found.
- No published notes on memory limits or on the SQL-table variant of the Orbis Historical delivery.

## Key question 5 — Documentation of the Orbis ownership "Links" historical files and building ownership time series

### Takeaway
The only concrete, readable documentation of the historical Links files is in code: Orbis Historical ships one `Links_YYYY.txt` per year (2007 onward) plus an `Entities.txt`, with columns `Subsidiary BvD ID`, `Shareholder BvD ID`, `Type of relation` (values include `HQ`, `DUO 50`), `Direct %`, `Total %`, `Direct % (only figures)`, `GUO 25`, `GUO 25 JO`, `GUO 25c`, `GUO 50`, `GUO 50c`, `Information date`, and `Active/archived`; an ownership spell is built as first/last `Information date` per (subsidiary, shareholder) pair across yearly files, with archived links from the latest file supplying end dates.

### Cited Findings
- Reading rule: for 2007–2019 keep `links['Active/archived']=='active'` per yearly file; from the last available year keep both, writing archived links to a separate file. Code: `links = dd.read_csv(own_hist_fd + "Links_" + str(yr) + ".txt", sep='\t', ...); links = links[(links['Subsidiary BvD ID'].str[:2]==ctry) & (links['Active/archived']=='active')]`. — [processHist.py readHistLinks](https://github.com/YiLulululu/EquityOwnershipStructure/blob/main/processHist.py)
- Entity typing from `Entities.txt`: column `'BvD ID of the subsidiary or shareholder'` and `'Entity type'` with codes such as `I` (industrial), `E, F, P, V, Y` (financial/fund-type owners) used to separate investor-owners from corporate owners. — same file
- Link filtering: drop branch IDs containing '-' (`~links['Subsidiary BvD ID'].str.contains('-')`), drop `Type of relation == 'HQ'`, select majority links by `links['Direct % (only figures)']>50` or `Type of relation == 'DUO 50'`; foreign ultimate owners identified by `GUO 50`/`GUO 50c` prefix != 'GB'. — same file
- Spell construction: sort by `Information date` year, take first appearance per `(Subsidiary BvD ID, Shareholder BvD ID)` as `first_yr`, set `last_yr` to the file year; for archived links take first and last information dates; missing information dates are filled with the file year (`fillna(str(yr))`). — same file (`mergeHistLinks`)
- Current (non-historical) link tables on Moody's DataHub / Orbis: `links_current` with `subsidiary_bvd_id, shareholder_bvd_id, total_only_figures_, guo_25c, guo_25, guo_50c, guo_50, guo_25_jo, guo_25c_jo`; `basic_shareholder_info` with `ish_/guo_/duo_bvd_id_number`, `_country_iso_code`, `_total_`; `controlling_shareholders`, `branches`, `hq`. Doc string: "One row per shareholder link, so joining on subsidiary fans out by the number of recorded shareholders." — [schemas.py](https://github.com/usama-jamal/firmpanel/blob/main/src/firmpanel/schemas.py)
- Recursive ultimate-owner resolution in DuckDB with threshold on `total_only_figures_ > 50`, one parent per child (`QUALIFY row_number() OVER (PARTITION BY child ORDER BY parent) = 1`), path list for cycle detection (`NOT list_contains(w.path, e.parent)`), depth cap 20 flagged as `depth_capped`. — [ownership.py](https://github.com/usama-jamal/firmpanel/blob/main/src/firmpanel/ownership.py)
- WRDS first-level ownership tables (`ob_all_cur_shh_1st_level_l`, `ob_all_subs_first_level_l`) carry percentages as `varchar(7)` with special tokens, and an information date that "do[es] not turn a current snapshot into historical ownership at arbitrary past dates"; "First-level records are not a ready-made ultimate-owner graph." — [bvd.md](https://github.com/piotrek-orlowski/claude-wrds-public/blob/main/skills/wrds-governance/references/bvd.md)
- Library snippets: "ORBIS includes over 117 million ownership/subsidiary links ... Key features of the ownership links include the nationality of the owner, ultimate vs. direct ownership, and the type and sector of owner" and ownership history "from 2007" (HBS/Yale, snippet only). — [Yale Historic](https://guides.library.yale.edu/BVDORBIS/Historic); [HBS](https://www.library.hbs.edu/databases-cases-and-more/datasets/orbis-historical)
- Nessa et al. (JAR) treat WRDS web-export ownership fields `guodirect=="-"` and `guototal=="n.a."` as missing when deduplicating. — [JAR_63 do-file](https://github.com/jusi-aalto/stata-accounting-research/blob/master/references/JAR_63_2_npstv_nessa_etal.do)

### Inferences
- A time series of control links from Orbis Historical should be built from the yearly `Links_YYYY.txt` files using `Information date` and `Active/archived`, not from the current-ownership tables, whose "information date" is a last-update stamp.
- Pre-computed `GUO 25/50(c)` columns exist in the historical Links files themselves, so a GUO-by-year panel can be formed without a graph walk; the graph walk is needed only when GUO fields are missing or a different threshold is wanted.

### Gaps
- The official Moody's/BvD "Ownership manuals" (WU PDF) and any Orbis Historical data dictionary for Links were not readable; the exact semantics of `Active/archived`, `JO` (joint-ownership) variants and the `c` suffix (including self-ownership per firmpanel's docstring "Global ultimate owner, 25% incl. self-ownership") could not be confirmed from vendor text.
- No documentation of how BvD ID changes propagate into Links files was found.

## Cross-cutting: concrete rule snippets for the tricky parts (quick reference, all quoted above with sources)

- One statement per firm-year, "unconsolidated first" cascade (Stata): gjardad `create_firm_year.do` steps 1–10.
- "Consolidated first" with annual-report preference and latest closing date (R/dplyr): Gassen `download_data.R` / rct25 `create_orbis_panel_de.R` (`cc_rank`, `ft_rank`, `closdate == max`).
- Simple priority U1 < U2 < C1 < C2 (Stata): M2DE-Thesis (`cons_priority`), and reverse (prefer C) in JAR 60 (`drop if dup==1 & substr(CONSCODE,1,1)=="U"`).
- Kalemli-Özcan hybrid (prefer C when values differ; otherwise the firm's majority mode) (R): Big-Bang `prioritize_duplicates_majority`.
- Dropping LF: EquityOwnershipStructure (`conscode!='LF'`); firmpanel instead groups LF with consolidated codes.
- Number of months ≠ 12: drop (`$5=="12"` awk; `nr_months == "12"` R/SQL; `keep if nr_months=="12"` Stata) or rank 12-month first (fin5). No repo annualises partial-year statements.
- Multiple closing dates in a year: keep latest closing date (Gassen; panel-e2tree; fin5) after consolidation/filing-type ranking.
- Fiscal-year assignment: calendar year of closing date (most repos) vs June cut-off (Kalemli-Özcan convention: Big-Bang, Nessa et al.) vs January-closers-belong-to-previous-FY (TJN).
- Currency/units: use EUR or USD file variants directly (panel-e2tree, TJN "absolute EUR, NOT thousands"); or divide WRDS USD values by `EXCHRATE` (gjardad); retain `orig_units`, `orig_currency`, `exchrate` (bvd.md).
- Deflation: sectoral PPI at NACE 3-digit with 2-digit fallback (M2DE-Thesis); IMF exchange rates (MM2026). No Orbis-specific deflator tutorial found.
- Outliers: winsorise ratios at 1/99 (panel-e2tree); size filter employees ≥ 10 or total assets ≥ 1 M or operating revenue ≥ 250 k (EquityOwnershipStructure).
- BvD ID changes: not handled in any fetched code; the only statement is that the Historical product "creates a panel incorporating sector and ID changes" (Kalemli-Özcan via Princeton FAQ snippet).
- Country selection: `substr(BvD ID,1,2)` in awk, `LIKE 'XX%'` in SQL/WRDS, `.str[:2]==ctry` in pandas/dask.
