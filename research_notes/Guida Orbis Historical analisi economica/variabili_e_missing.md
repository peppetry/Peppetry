## Q2. How missing values are represented ("n.a.", "n.s.", "n.d.", "-", empty, 0) and the n.a. vs n.s. distinction

### Takeaway
Practitioner code that reads Orbis exports consistently treats the string tokens `n.a.`, `n.s.`, `n.d.` and `-` as missing; in BvD terminology `n.a.` = not available and `n.s.`/`-` = not significant. No official BvD text defining exactly when `n.s.` is emitted (e.g., ratios with non-positive denominators) could be retrieved, and no source was found that says whether literal zeros in financial items are ever placeholders for missing.

### Cited Findings
- Kalemli-Özcan et al. describe the tokens as: "-" (not significant) or "n.a." (not available) are codes used in the data, particularly in ownership fields. — [search extract] attributed to [Kalemli-Özcan et al., NBER w21558 rev.1](https://www.nber.org/system/files/working_papers/w21558/revisions/w21558.rev1.pdf) / [UMD data description](https://www.econ.umd.edu/sites/www.econ.umd.edu/files/pubs/Data_Description_2015_09_final.pdf).
- "n.a." is also used in the subsidiaries/financials context "to mark subsidiaries when only consolidated information from the parent company is available", i.e. the subsidiary's figures are covered by the parent's consolidated accounts. — [search extract] from the result set that included [KPMG/Bocconi methodological notes for DG ECFIN](https://commission.europa.eu/document/download/57a70bd7-5e6b-4822-bd49-1f0fa5d836c2_en?filename=dg_ecfin_am_final_report_pillar_1_methodological_notes.pdf) and [World Bank PRWP 10261](https://documents1.worldbank.org/curated/en/099800112132221252/pdf/IDU03d9586040b28504839081120922e33694f65.pdf); exact originating page not confirmable.
- Stata replication code for a published profit-shifting paper strips both tokens before `destring`: `replace \`var'=subinstr(\`var', "n.a.","", 10)` and `replace \`var'=subinstr(\`var', "n.s.","", 10)`. — [direct read of search fragment] [dfichmann/Offshore_Profit_Shifting_Replication.jl, PrepOrbis.do](https://github.com/dfichmann/Offshore_Profit_Shifting_Replication.jl/blob/main/ReplicationFiles/0-confidential-data-replication-files/FDIUS/PrepOrbis.do).
- A Python pipeline reads Orbis CSV exports with `pd.read_csv(financial_csv, na_values=["n.d.", "n.s."])`, i.e. `n.d.` appears as a missing marker in some exports (consistent with a non-English interface language). — [direct read] [JJMorbix/orbis-data-pipeline, Preprocessing/preprocessing.ipynb](https://github.com/JJMorbix/orbis-data-pipeline/blob/main/Preprocessing/preprocessing.ipynb).
- Another pipeline maps `{"n.a.": None, "n.s.": None, "-": None, "": None}` before numeric parsing of Orbis columns such as "Operating revenue (Turnover) m USD Last avail. yr" and "Number of employees Last avail. yr". — [direct read of search fragment] [EnriqueForero/rues-linker_v2, notebook 10](https://github.com/EnriqueForero/rues-linker_v2/blob/main/notebooks/10_vincular_exportadores_orbis_fdi.ipynb).
- A parser comment: "Parses Orbis numeric values which may contain commas, comparison operators, or N/A markers". — [direct read of search fragment] [ROHITH-RAMAKRISHNAPPA/Irish-SME-Dissolution-Risk, src/extract_orbis.py](https://github.com/ROHITH-RAMAKRISHNAPPA/Irish-SME-Dissolution-Risk/blob/main/src/extract_orbis.py).
- WRDS ownership tables store percentages as `varchar(7)` strings containing "special tokens, missing values, and bounds"; the author advises to "preserve raw values and separate parseable numeric values from special tokens". — [direct read] [claude-wrds-public bvd.md](https://github.com/piotrek-orlowski/claude-wrds-public/blob/main/skills/wrds-governance/references/bvd.md).
- Gal (2013) sets variables to missing when they look like imputations: "Operating revenues and the number of employees are set to missing when a large number of firms in a country and year have the same value of a given variable, suggesting rounded or imputed values." — [search extract] [Gal 2013, OECD](https://www.oecd.org/content/dam/oecd/en/publications/reports/2013/05/measuring-total-factor-productivity-at-the-firm-level-using-oecd-orbis_g17a22d0/5k46dsb25ls6-en.pdf).

### Inferences
- In the WRDS/SQL and Orbis Historical tab-delimited deliveries the numeric columns are typed (`double precision`), so missing values arrive as empty cells/NULL rather than as text tokens; the `n.a.`/`n.s.` tokens are a feature of web-interface Excel/CSV exports. Code that handles both forms is the safe default.
- The "comparison operators" mention above (e.g., `>`/`<` prefixes) is consistent with ownership-percentage bounds and with some size-band fields, not with the Global format financial items.
- Treat literal 0 in EMPL, STAF, MATE and TURN with suspicion in registry-sourced filings (see Q4): a zero in an item the filing was not required to disclose is more likely "not reported" than "zero".

### Gaps
- No official BvD text was retrieved defining when `n.s.` is emitted (expected: ratios whose denominator is ≤ 0 or whose result is outside a plausible range). Needs the Orbis help pages.
- No source found on whether BvD ever stores 0 for undisclosed items; the only related evidence is the Gal (2013) mass-point rule above.
- Whether Orbis Historical flat files contain any text token in numeric columns (vs. empty) could not be verified from a file header.

## Q3. Units and currency: thousands vs units, "Original units", "Original currency", "Exchange rate from original currency", EUR/USD/local versions

### Takeaway
The flat files carry three provenance fields—`orig_units`, `orig_currency`, `exchrate`—and WRDS/Orbis Historical financial tables come in currency-specific variants (e.g., `..._usd_l`, EUR folders). Web-interface exports let the user choose the scale ("th" or "m"), so column headers such as "Operating revenue (Turnover) m USD" exist. I could not verify from a reachable source that Orbis Historical flat-file values are in thousands; this is the single most important thing for the user to confirm from their own file documentation.

### Cited Findings
- WRDS Orbis financial table fields: `nr_months` is `varchar(2)` ("period length is not safely assumed numeric/12"); `orig_units`, `orig_currency` = "Original units/currency fields; retain when comparing converted values"; `exchrate` = "double precision, exchange rate from original currency". The author warns: "Product currency labels do not by themselves establish measurement scale." and "Select the appropriate industrial, bank, or insurance statement family and currency variant explicitly." — [direct read] [claude-wrds-public bvd.md](https://github.com/piotrek-orlowski/claude-wrds-public/blob/main/skills/wrds-governance/references/bvd.md).
- WRDS column labels: "ORIGINAL UNITS", "ORIGINAL CURRENCY", "EXCHANGE RATE FROM ORIGINAL CURRENCY"; market cap label is "MARKET CAPITALISATION (MIL)". — [direct read] [rs-kellogg explore.ipynb](https://github.com/rs-kellogg/wrds_workshop_public/blob/main/docs/explore.ipynb).
- The Kalemli-Özcan "Processing Orbis Historical Disk" guide describes folders containing financial variables in USD and EUR currencies (plus original currency). — [search extract] [Processing Orbis Historical Disk (Kalemli-Özcan site)](https://sebnemkalemliozcan.com/assets/workingpapers/Processing%20Orbis%20Historical%20Disk%20FINAL2.pdf); mirror: [orbisdocumentation.pdf](https://fanjt.weebly.com/uploads/1/9/4/7/19473457/orbisdocumentation.pdf).
- Web-export column header example showing user-selected scale: "Operating revenue (Turnover) m USD Last avail. yr". — [direct read of search fragment] [EnriqueForero/rues-linker_v2](https://github.com/EnriqueForero/rues-linker_v2/blob/main/notebooks/10_vincular_exportadores_orbis_fdi.ipynb).
- A French-coverage Stata script divides sales by `EXCHRATE` (to return to original currency) and later rescales by 10^-6 before comparing to national accounts. — [direct read] [gjardad assess_orbis_coverage_FR_subset.do](https://github.com/gjardad/Carbon-policy-and-reallocation/blob/main/assess_orbis_coverage_FR_subset.do).
- Bank Focus (same vendor) keeps separate `usd_exchange_rate` and `eur_exchange_rate` and `original_unit` fields; `closing_date` there is `varchar(8)` unlike Orbis's date-typed `closdate`. — [direct read] [claude-wrds-public bvd.md](https://github.com/piotrek-orlowski/claude-wrds-public/blob/main/skills/wrds-governance/references/bvd.md).

### Inferences
- Interpretation of the three provenance fields consistent with the above: `orig_units` records the scale of the source filing (units / thousands / millions), `orig_currency` the filing currency, and `exchrate` the rate used to convert from the original currency into the currency of the table/folder (USD, EUR). Dividing a converted value by `exchrate` returns the original-currency amount, which is exactly what the gjardad script does.
- Because `orig_units` varies across filings of the same firm, a unit change at source (e.g., a firm switching from units to thousands) is a plausible mechanism for the "very large jumps" users report; grouping by `bvdid` and flagging changes in `orig_units` or implausible year-on-year ratios (×1000 or ÷1000) is the natural check. No source was retrieved that documents a specific unit error in BvD data.
- The common convention in Orbis Historical/WRDS deliveries is thousands of the table currency, with `empl` in units; this is **not** verified here and must be confirmed against the file's README.

### Gaps
- Direct documentary confirmation of "values in thousands" for Orbis Historical flat files (the search for this was refused after the budget was exhausted; the Kalemli-Özcan processing guide is blocked).
- The exact value domain of `orig_units` (e.g., "units", "thousands", "millions", "billions") and whether `exchrate` is period-average or closing-date rate: not found.
- Any documented BvD errata on units: none found.

## Q4. Employment: how "Number of employees" is collected, headcount vs FTE, country variation, zeros and estimates

### Takeaway
Sources agree that the employee figure's definition depends on country and data provider, that it is frequently missing or implausible (e.g., jumps between 0 and 43,000), and that OECD practice is to set it to missing when many firms share an identical value (rounded/imputed figures). Nothing retrievable states whether it is headcount or FTE or flags BvD "estimated" employee counts.

### Cited Findings
- "The exact definition of employment information in Orbis depends on each country and data provider." — [search extract] attributed to [IAB FDZ Methodenreport 04/2018, "Orbis-ADIAB: From record linkage key to research dataset"](https://doku.iab.de/fdz/reporte/2018/MR_04-18_EN.pdf) (German record-linkage project between Orbis and IAB employer data).
- Researchers found "significant inconsistencies in employee numbers in the Orbis database, with records showing extreme variations such as ranging between 0 and 43,000 employees with unexplained jumps within short time periods", and that "when companies have multiple establishments, a total number of employees cannot be calculated if not all establishment data is available". — [search extract] same IAB report and/or [JRC FOWN manual](https://publications.jrc.ec.europa.eu/repository/bitstream/JRC118266/jrc118266_fown_manual.pdf).
- "Operating revenues and the number of employees are set to missing when a large number of firms in a country and year have the same value of a given variable, suggesting rounded or imputed values." — [search extract] [Gal 2013, OECD](https://www.oecd.org/content/dam/oecd/en/publications/reports/2013/05/measuring-total-factor-productivity-at-the-firm-level-using-oecd-orbis_g17a22d0/5k46dsb25ls6-en.pdf).
- Bajgar et al. (2020) benchmark Orbis employment and value added against OECD STAN, MultiProd and DynEmp and find Orbis "is tilted toward larger, older, and more productive firms, even within each size class"; Orbis is more suitable for studies that "take a global perspective rather than making comparisons across countries", "analyse top performers and multinationals rather than underperforming firms", and "focus on mean performance or within-firm changes rather than on the entire firm distribution or entry and exit". — [search extract] [Bajgar, Berlingieri, Calligaris, Criscuolo, Timmis, OECD STI WP 2020/06](https://www.oecd.org/content/dam/oecd/en/publications/reports/2020/05/coverage-and-representativeness-of-orbis-data_9628c322/c7bdaa03-en.pdf).
- Kalemli-Özcan et al. report that the raw data "may contain irregularities which result in data loss during standard cleaning" and that these issues "cause minimal coverage of small firms, extensive missing data, and poor national representation". — [search extract] [NBER w21558](https://www.nber.org/papers/w21558.pdf).
- Only firms with non-missing employment are retained in several analyses (employment missingness is a recognised selection step). — [search extract] [IAB MR 04/2018](https://doku.iab.de/fdz/reporte/2018/MR_04-18_EN.pdf).

### Inferences
- Because EMPL enters BvD's size classification and is reported by registries only where national law requires (memorandum item in notes to accounts, or none at all for abridged filers), missingness is concentrated among small firms and in countries whose registry filings omit the notes; this also explains why EMPL and STAF are often missing together.
- An employee count of exactly 0 for an active company with positive STAF is internally inconsistent and should be set to missing; a 0 with STAF also 0/missing in a registry filing is ambiguous (dormant vs undisclosed).

### Gaps
- Headcount vs FTE, and whether BvD stores "estimated" employee figures (the web interface shows an "estimated" flag in some country sources), could not be verified from any reachable page.
- No country-by-country table of employment sources was retrievable (the UCLA Anderson "BvD Filing Requirements for Companies Globally, January 2016" PDF — [link](https://www.anderson.ucla.edu/documents/areas/adm/acis/library/FilingRequirementsForCompaniesGloballyBureauVanDijk.pdf) — is the best candidate but is blocked).

## Q5. Statement-level metadata: Closing date, Number of months, Accounting practice, Audit status, Source, Filing type, Consolidation code — meanings and how to pick one statement per firm-year

### Takeaway
The consolidation codes have stable, widely reproduced definitions (C1/C2 consolidated, U1/U2 unconsolidated, LF limited financials, NF no financials). Filing type takes the values "Annual report" vs "Local registry filing", accounting practice "IFRS"/"Local GAAP"/"Accounting practice unknown". The dominant practitioner rule is: keep 12-month statements, assign fiscal year by closing date (June-1 cut-off in Kalemli-Özcan), then choose one consolidation scope per firm-year (unconsolidated for national-representativeness work; consolidated for group-level work), then prefer "Annual report" over "Local registry filing", then break ties by completeness/latest closing date.

### Cited Findings
- **Consolidation codes:** "C1: Consolidated account of a company-headquarter of a group, aggregating all companies belonging to the group (affiliates, subsidiaries, etc.), where the company-headquarter has no unconsolidated account. C2: Consolidated account of a company-headquarter of a group … where the company-headquarter also presents an unconsolidated account. U1: Account of a company with no consolidated account. U2: Account of a company with a consolidated account. LF: Account of a company with only a limited number of information/variables included. NF: Account of a company with no financial items/variables included." — [search extract] reproduced in [Kalemli-Özcan et al., Tinbergen DP 15-110](https://papers.tinbergen.nl/15110.pdf), [OECD 2010 "The OECD ORBIS database" (Ribeiro, Menghinello, De Backer)](https://www.oecd.org/content/dam/oecd/en/publications/reports/2010/03/the-oecd-orbis-database_g17a1e2e/5kmhds8mzj8w-en.pdf), [Bajgar et al. 2020](https://www.oecd.org/content/dam/oecd/en/publications/reports/2020/05/coverage-and-representativeness-of-orbis-data_9628c322/c7bdaa03-en.pdf) and [Cravino & Levchenko online appendix](https://alevchenko.com/Cravino_Levchenko_Online_Appendix.pdf). Third-party reproductions of BvD text.
- **Duplicates by design:** "Duplicate accounts in Orbis data arise because companies may report both consolidated and unconsolidated statements in the same year or firms may switch the type of financial statements they report over time." — [search extract] [Kalemli-Özcan et al., NBER w21558 rev.1](https://www.nber.org/system/files/working_papers/w21558/revisions/w21558.rev1.pdf).
- **Fiscal-year assignment:** "The account closing date (CLOSEDATE) variable is used to correctly assign the calendar year … if the closing date is after or on June 1st, the current year is assigned" (otherwise the previous year). — [search extract] [Kalemli-Özcan et al., NBER w21558 rev.0](https://www.nber.org/system/files/working_papers/w21558/revisions/w21558.rev0.pdf). - **Practitioner selection rule 1 (German panel, WRDS files):** filter `nr_months == "12"`; rank `cc_rank = C1→4, C2→3, U1→2, other→1` and keep the max; rank `filing_type == "Annual report"` (2) above others (1); among remaining duplicates keep the latest `closdate`, then the row with fewest missing values (`n_missing = rowSums(across(everything(), ~ is.na(.x)))`), and raise an error if duplicates persist. — [direct read] [Leslie-creat/rct25 create_orbis_panel_de.R](https://github.com/Leslie-creat/rct25/blob/main/code/create_orbis_panel_de.R).
- **Practitioner selection rule 2 (listed-firm panel):** "De-dup rule (data-review): NR_MONTHS==12, CONSCODE priority C1<C2<U1<U2, tie-break by largest TOAS." — [direct read of search fragment] [narangtanmay/proxyengine-demo, loaders.py](https://github.com/narangtanmay/proxyengine-demo/blob/main/loaders.py).
- **Practitioner selection rule 3 (national coverage, France):** "if there are consolidated and unconsolidated obs keep the unconsolidated one", then a 10-step cascade preferring non-missing value added, sales, labour, capital, then the largest values, then random. — [direct read] [gjardad assess_orbis_coverage_FR_subset.do](https://github.com/gjardad/Carbon-policy-and-reallocation/blob/main/assess_orbis_coverage_FR_subset.do).
- **Practitioner selection rule 4 (published paper, gross profits):** "we first keep data with the filing type of 'annual report' instead of 'local registry filing'. If we still observe multiple sources … we only keep data with the consolidation type of 'C2'". — [direct read of search fragment] [ahmadlp.github.io, markups-as-shadow-tariffs](https://github.com/ahmadlp/ahmadlp.github.io/blob/main/public/sources/markups-as-shadow-tariffs.md).
- **Practitioner selection rule 5 (UK suppliers):** takes the first letter of the consolidation code (U/C); when values differ across scopes gives priority to consolidated; prefers "Annual report" over "Local registry filing" for the same firm-year. — [direct read] [gabpiazza/Big-Bang 01_dataprep_C.R](https://github.com/gabpiazza/Big-Bang/blob/main/01_dataprep_C.R).
- WRDS guidance: "Start with one bvdid and one fiscal year. Identify multiple consolidations, filing types, closing dates, and annual versus interim periods before choosing the panel key. Do not collapse them by arbitrary maximum values." and "Fiscal closing date is not public filing availability." — [direct read] [claude-wrds-public bvd.md](https://github.com/piotrek-orlowski/claude-wrds-public/blob/main/skills/wrds-governance/references/bvd.md).
- Arndt (2023): "Choosing different types of financial statements in ORBIS will lead to different firms entering calculations"; "there is a reporting lag of about 2 years on average, with differences in coverage of particular variables depending on when the product is released". — [search extract] [Arndt, "When Should We Believe Research Using ORBIS Firm Data?", SSRN 4584106](https://papers.ssrn.com/sol3/papers.cfm?abstract_id=4584106).

### Inferences
- For economic analysis at the legal-unit/national level (productivity, employment, firm dynamics) the appropriate choice is U1 ∪ U2 (plus C1 only when no unconsolidated statement exists, since C1 firms by definition have none); for group-level finance the choice is C1 ∪ C2 with U1 as fallback. Mixing C2 and U2 for the same firm-year double counts.
- LF and NF rows should be dropped from financial analysis but retained as evidence that the firm existed/filed in that year.
- `nr_months` ≠ 12 rows (short or long first/last fiscal years, changes of year-end) should either be dropped or annualised for flow variables only; stock variables (TOAS, SHFD, EMPL) need no annualisation.
- Because `nr_months` is stored as a 2-character string on WRDS, numeric comparisons must cast it first.

### Gaps
- Value domain of "Audit status" (expected: e.g. Audited/Unqualified, Qualified, Not audited) and of "Source (for publicly quoted companies)" (expected: data providers such as exchange/press-release/annual-report sources) was not retrievable.
- Whether Orbis Historical contains interim (non-12-month) statements at all or only annual accounts: not verified.

### Inferences
- Status, status date, legal form, NACE code, size category, listed flag, independence indicator and GUO are all **as-of-snapshot** attributes. In a single Orbis Historical vintage, a firm dissolved in 2015 carries "Dissolved" on all of its 1995–2015 financial rows. Any survival/exit analysis must therefore (a) use the status date rather than the status itself to time the event and (b) treat "Active" in the latest vintage as right-censoring; and sector/size assignments at historical dates should be derived from the financial rows (OPRE/TOAS/EMPL thresholds) or from stacked vintages, not from the snapshot field.
- Because size category is determined by the most recent available OPRE/TOAS/EMPL and listing status, "category_of_company" in WRDS size-split products (`_l`, `_m`, `_s`) is a sampling-frame variable, not a firm characteristic for a given year; firms migrate between the L/M/S products across vintages, which is a mechanism for apparent entry/exit.
- "Active (dormant)" and "Active (default of payment)" firms normally have NF/LF or zero-activity statements; keep them in population counts but exclude from productivity samples.

## Q7. Known pitfalls: BvD ID changes, duplicate IDs across country files, consolidated vs unconsolidated duplicates, unit jumps, negative values, 10-year window, reporting lag, country filing exemptions

### Takeaway
The best-documented pitfalls are: BvD IDs change when a firm changes national ID/registry office or legal form (BvD supplies a correspondence table / ID-change lookup); consolidated and unconsolidated statements coexist for the same firm-year; the web product keeps only a rolling 10-year window per firm and has a ~2-year reporting lag; and coverage of small firms depends on national filing rules (UK small-company "filleted" accounts omit the P&L). Evidence on duplicate BvD IDs across country files and on negative-asset records is anecdotal in the retrieved material.

### Cited Findings
- **BvD ID changes:** "When a company moves from one area to another with a different office collecting information, the company will get a new national ID, thus the BvD ID number changes." Researchers merging data from several disks/downloads "may encounter occasional BvD ID changes over time". Remedies: "request the 'correspondence table' of BvD IDs from their BvD representative", or use "the dedicated BvD ID Change Lookup tool at idchanges.bvdinfo.com". — [search extract] attributed to [Kalemli-Özcan et al., UMD data description](https://www.econ.umd.edu/sites/www.econ.umd.edu/files/pubs/Data_Description_2015_09_final.pdf) and the result set including [World Bank PRWP 10261](https://documents1.worldbank.org/curated/en/099800112132221252/pdf/IDU03d9586040b28504839081120922e33694f65.pdf). Also "Companies encounter a BvD ID change if they change legal form." — [search extract] [NBER w21558 rev.0](https://www.nber.org/system/files/working_papers/w21558/revisions/w21558.rev0.pdf).
- **Ownership duplicates from ID changes:** "changing BvD ID numbers of shareholders, in combination with extrapolation of ownership shares, can lead to a legacy of duplicate shareholders with old and new BvD IDs." — [search extract] (same result set).
- **Consolidated/unconsolidated duplicates:** see Q5 (Kalemli-Özcan rev.1).
- **10-year rolling window in the web product:** "the ORBIS' online portal updates company data when new data becomes available, however, it only provides 10 years of financial information for a company … when the latest financial data of a company becomes available in 2016, the ORBIS' online portal will drop all data of this company before 2007". — [direct read of search fragment] [ahmadlp.github.io paper page](https://github.com/ahmadlp/ahmadlp.github.io/blob/main/public/paper-reader-data/markups-as-shadow-tariffs/paper.xml). - **Representativeness:** Orbis is "tilted toward larger, older, and more productive firms, even within each size class". — [search extract] [Bajgar et al. 2020](https://www.oecd.org/content/dam/oecd/en/publications/reports/2020/05/coverage-and-representativeness-of-orbis-data_9628c322/c7bdaa03-en.pdf).

- **Linking by security IDs:** "A security identifier can have multiple securities per firm and can change over time"; the WRDS linking tool "does not supply one-to-one company mappings or validate their historical intervals". — [direct read] same file.

### Inferences
- "Duplicate BvD IDs across country files" most plausibly arises when the same legal entity appears in two national files after a change of registered country or when Orbis Historical country splits are by current (snapshot) country while financial rows carry the historical country; de-duplicating on `bvdid × closdate × conscode × filing_type` across all country files before any analysis is the defensive step. No retrieved source documents this explicitly.
- Extreme year-on-year jumps (×1000) are consistent with a change in `orig_units` or with mixing an "Annual report" and a "Local registry filing" row for the same year (different reporting rules yield different values—see Q5); check both fields before winsorising.
- The ~2-year reporting lag means the last two closing years in any vintage are incomplete and biased toward large/early filers; truncating the panel two years before the vintage date is standard.

### Gaps
- No source quantifies the frequency of BvD ID changes or documents a within-vintage duplicate-ID problem in Orbis Historical.
- No documentary evidence on negative total assets or negative employees in BvD files beyond practitioners' drop rules.
- Country tables of what small firms must file (DE, IT, FR, ES, NL) and the resulting Orbis missingness of TURN/OPRE/STAF/EMPL were not retrievable in this run; the three PDFs listed above are the primary references to consult.
